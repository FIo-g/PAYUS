04 state="failed" 결제 실패

에러 X 아이콘 등장 + shake. “왜” 실패했는지 + “어떻게” 해결하는지를 한 화면에. 충전 CTA가 가장 굵게.

설계 노트

상태 전이
idle ──[탭 결제하기]──▶ processing
processing ──[성공]──▶ success
processing ──[실패]──▶ failed
success ──[확인]──▶ 모달 닫힘
failed ──[충전하기]──▶ 충전 화면
React Props (TSX 변환 시)
type Props = {
  state: 'idle' | 'processing' | 'success' | 'failed';
  merchant: { name; category; thumbnail; };
  amount: number;
  cashbackAmount: number;
  cashbackRate: number;
  balanceAfter: number;
  coupon?: { name; discountAmount; };
  transactionId?: string;  // success
  errorCode?: string;      // failed
  errorMessage?: string;   // failed
  shortfall?: number;      // failed (잔액 부족 시)
  onConfirm: () => void;
  onCancel: () => void;
  onViewReceipt?: () => void;
  onRecharge?: () => void;
};
Framer Motion 매핑
· 체크/X 아이콘: motion.div + spring(0.34, 1.56, 0.64, 1)
· check path: motion.path + pathLength 0 → 1, 320ms 지연
· 본문 텍스트/카드: staggerChildren: 0.08로 순차 등장
· failed의 흔들림: animate: {'{ x: [-6, 6, -4, 4, 0] }'}
· prefers-reduced-motion 시 spring → tween / shake 제거
결정 사항 · 확인 부탁
  • idle 화면에서 쿠폰 자동 선택 정책 — 기본 ON, 사용자가 끌 수 있게 한다는 가정.
  • success는 거래번호 + 금액 + 캐시백 3줄만 노출. 가맹점명은 의도적으로 생략 (영수증에서 확인).
  • failed의 “충전하기”가 Primary, “닫기”가 Secondary. 보통의 cancel-on-right 패턴 깨는 의도적 결정 — 사용자가 충전으로 빠르게 회복하도록.
  • processing은 최소 600ms 표시 권장 (너무 빠르면 “정말 처리됐나?” 의심). 실 결제 응답이 빨라도 의도적 딜레이.
